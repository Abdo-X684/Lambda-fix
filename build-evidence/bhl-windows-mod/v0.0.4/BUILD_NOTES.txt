Lambda-fix 0.0.4 - Windows package
==================================

RENUMBERED
----------
This package was published as 1.0.4. It was never a 1.x release - the
project is pre-release software and that numbering claimed a stable
interface it does not have. It is now 0.0.4 on the 0.x line, with the
beta tag starting at 0.1.8. The ZIP is byte-for-byte the same archive;
only its name changed, so its sha256 is unchanged.


WHAT CHANGED FROM 1.0.3
-----------------------
OP4 monsters and weapons dealt zero damage. Two defects, both fixed.

1) gamerules.cpp never filled the OP4 half of gSkillData.
   CGameRules::RefreshSkillData() assigned 86 fields - all Half-Life
   monsters and weapons. The 62 OP4 fields (gonome, pitdrone, voltigore,
   shocktrooper, shockroach, pitworm, geneworm, zombie_soldier,
   zombie_barney, ally classes, Otis, cleansuit scientist, OP4 player
   weapons) existed only in op4/reference/dlls/gamerules.cpp, which CMake
   does not compile.

   gSkillData.gonomeDmgOneBite was 0.0, so
       CheckTraceHullAttack(70, gSkillData.gonomeDmgOneBite, DMG_SLASH)
   connected with the player and dealt nothing.

   Fixed: all 62 fields assigned. 86 -> 148 fields, 0 missing relative to
   the reference implementation.

2) The sk_* cvars those fields read were never defined.
   game.cpp registered 255 sk_* cvars, all Half-Life. The 186 OP4 ones did
   not exist, so CVAR_GET_FLOAT returned 0 no matter what RefreshSkillData
   did.

   Fixed: 186 cvars defined with the stock OP4 skill.cfg values, and all of
   them registered. Definitions 435, registrations 435.
   Examples: sk_gonome_dmg_one_bite1 = 7, ...2 = 14, ...3 = 14,
             sk_gonome_health1 = 85, sk_gonome_dmg_guts1 = 10,
             sk_pitdrone_dmg_bite1 = 15, sk_voltigore_health1 = 320.

   A skill.cfg in the game directory still overrides these defaults, so the
   values are also correct on installations that ship one.
