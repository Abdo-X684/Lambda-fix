Lambda-fix 1.0.9 - Windows package
==================================

WHAT THIS IS
------------
1.0.4's exact 98-file gearbox_addon layout (OP4 damage + skill data from the
bhl-op4 tree), with two files changed: dlls/opfor.dll and MOD_MANIFEST.json.

WHAT CHANGED FROM 1.0.4
-----------------------
One function changed in the server DLL: CPushable::Move().

It is now a verbatim copy of the CPushable::Move() in the OP4 server you
uploaded and confirmed works (halflife-op4-updated, before commit 4f0d502e4
"[HL25] Backport fixes to pushable"):

  * no sv_pushable_fixed_tick_fudge, no frametime scaling;
  * a push requires IN_FORWARD or IN_USE to be held;
  * the speed clamp applies to a push only;
  * velocity accumulates, and on a push the player's velocity is set to the
    box's velocity - that sync is what produces object boosts.

Everything else the server did in 1.0.4 is unchanged: OP4 monster/weapon
damage, all 62 OP4 gSkillData fields, all 186 OP4 sk_* cvars, impulse 101,
speedrun core.

HOW MOVE IS CALLED
------------------
Touch() and Use() call Move() exactly as in your server. PushThink() runs every
frame and, if a player overlaps the box, calls that same Move(). It is a safety
net only: it adds no movement of its own, it just calls the same function the
engine would call. If your server's Touch path works, the result is identical.

Verified in the binary (not just in the source): the compiled Move() contains
  test byte ptr [toucher+0x180], 0x28    ; IN_FORWARD|IN_USE gate on push
  clamp inside "if (push && length > MaxSpeed())"
  unconditional "toucher->velocity = box->velocity"
and the touch-only build of 1.0.4 does not contain that gate - it has the HL25
form instead. PushThink is present as ?PushThink@CPushable@@QAEXXZ.
