THE BOOST NOW HAPPENS WHEN YOU LET GO OF E
------------------------------------------
You said: "I should go with the object fast when I release E, not while I'm
holding E."

Root cause, in one line of Valve's Move():

    pevToucher->velocity.x = pev->velocity.x;
    pevToucher->velocity.y = pev->velocity.y;

That copies the box's velocity onto the player on every contact. While you
hold E, Use() calls Move() every frame, so that copy fires ~60 times a second
and drags you along with the box. When you let go, the copy stops and there is
nothing left to launch you with. That is exactly the "fast while holding it"
behaviour you described.

WHAT CHANGED
------------
1. func_break.cpp - CPushable::Move()
   The player is no longer dragged while +use is held. Instead the box's
   horizontal velocity is recorded as a peak on the player:

       if (+use held)   store max(box velocity) on the player, do not move him
       else             keep the original copy (a normal walk-into push still
                        moves you exactly as before)

2. player.h - two new members
       Vector m_vecPushBoost;
       bool   m_bPushBoostArmed;

3. player.cpp - CBasePlayer::PreThink()
   On the exact frame +use is released, the stored peak is put on the player:

       if (m_bPushBoostArmed && (m_afButtonReleased & IN_USE)) {
           pev->velocity.x = m_vecPushBoost.x;
           pev->velocity.y = m_vecPushBoost.y;
       }
       m_bPushBoostArmed = false;

   Cleared the same frame, so a stored value can never fire later by accident.
   Also cleared in CBasePlayer::Spawn() so it never survives a respawn.

WHY NOT COPY ON RELEASE INSTEAD
-------------------------------
Tested this on paper first. The box accumulates +player_speed per frame:

    frame 1: 320 u/s   travelled   5 units
    frame 2: 640 u/s   travelled  16 units
    frame 3: 960 u/s   travelled  32 units
    frame 4: 1280 u/s  travelled  53 units
    frame 5: 1600 u/s  travelled  80 units  <- outside the 64-unit use radius

The box leaves reach by frame 4-5, so by the time you release, PlayerUse finds
nothing to call Move() on. Waiting for a natural copy on release cannot work.
Storing the peak while the box is still in contact is what makes the launch
survive.

PushThink / FindTouchingEntity: still absent. Nothing runs per-frame on the box.
