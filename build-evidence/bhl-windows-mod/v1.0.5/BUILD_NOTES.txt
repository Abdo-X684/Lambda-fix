Lambda-fix 1.0.5 - Windows package
==================================

WHAT THIS IS
------------
1.0.4 with one server DLL replaced. Same 98 files, same layout
(gearbox_addon/), same licences. Only two things differ from 1.0.4:

  dlls/opfor.dll        1,675,264 -> 1,675,776 bytes
  MOD_MANIFEST.json     12,137    -> 12,315 bytes

That is deliberate: 1.0.4 works for you, so this build changes as little as
possible.

WHAT CHANGED IN THE DLL
-----------------------
func_pushable: boxes can be pushed and pulled again.

HL25 (client build 8684) broke func_pushable for every mod built on this SDK.
ValveSoftware/halflife#3639 reports boxes that cannot be moved in Counter-Strike:
Condition Zero unless the player runs

    sv_pushable_fixed_tick_fudge 15000      or      fps_max 60

The arithmetic: Move() added

    pev->velocity += pevToucher->velocity * factor      every frame

and for a pull factor was multiplied by

    gpGlobals->frametime * 15

At 60 fps that is 0.25; at 240 fps it is 0.0625. A push was additionally gated
on the engine delivering a touch to a MOVETYPE_PUSHSTEP entity, and the report
is that boxes do not move at all, which points at the touch never arriving.

Fixed by assigning velocity instead of accumulating it, and by driving the box
from its own think instead of waiting for a touch:

  PushThink()          runs every frame, finds a player overlapping the box
  USE held   -> pull   box keeps pace with the player, capped at MaxSpeed
  USE free   -> push   box takes the player's velocity, capped at MaxSpeed
  Touch()              kept as a fast path, no longer required
  Move()               kept as a wrapper over DriveFromToucher()

sv_pushable_fixed_tick_fudge is no longer consulted, so the value in the user's
config does not matter.

WHAT I GOT WRONG EARLIER
------------------------
My first 1.0.5 build was wrong and has been replaced. It shipped an opfor.dll
built from the halflife-op4-updated tree (1,860,608 bytes) instead of this
tree, which changed 21 files and the package layout. If you still have that ZIP
(sha256 beginning 8e24d529), delete it. The correct ZIP begins 80f0239f.

Night vision is not a change in this build. I edited EF_DIMLIGHT ->
EF_BRIGHTLIGHT in bhl-op4/player.cpp, but this tree already uses
EF_BRIGHTLIGHT everywhere (zero occurrences of EF_DIMLIGHT in it), so that edit
was a no-op here. If the suit light looks like a cone rather than an omni
light, the cause is somewhere else and I have not found it.
