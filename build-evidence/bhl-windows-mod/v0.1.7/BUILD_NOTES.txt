Lambda-fix 0.1.7 - Windows package
==================================

RENUMBERED
----------
This package was published as 1.1.7. It was never a 1.x release - the
project is pre-release software and that numbering claimed a stable
interface it does not have. It is now 0.1.7 on the 0.x line, with the
beta tag starting at 0.1.8. The ZIP is byte-for-byte the same archive;
only its name changed, so its sha256 is unchanged.


impulse 101 NOW GIVES ALL NINE OP4 WEAPONS
------------------------------------------
Your report was exact: 1.1.6 gave the weapons, but not all of them.

1.1.6 added only six OP4 weapons. The OP4 reference list has nine. The three
that were still missing:

    weapon_grapple
    weapon_sniperrifle
    weapon_displacer

All three were already registered, compiled and precached in our tree
(LINK_ENTITY_TO_CLASS in CGrapple.cpp / CSniperRifle.cpp / CDisplacer.cpp,
plus UTIL_PrecacheOtherWeapon for each in weapons.cpp) and all three are wired
on the client for prediction (hl_weapons.cpp). They were simply never added
to the impulse 101 list.

1.1.7 appends them after pipewrench, in the same order the stock OP4 server
uses, and keeps the reference's commented-out ammo_762 line.

MATCHED AGAINST THE REFERENCE, NOT BY EYE
-----------------------------------------
The list was compared mechanically - both sides tokenised, comments and
whitespace ignored - against twhl-community/halflife-op4-updated
dlls/player.cpp case 101:

    reference items: 33
    our items      : 33
    IDENTICAL      : True

Both lists end with the same nine, in the same order:

    weapon_eagle  weapon_sporelauncher  weapon_shockrifle
    weapon_knife  weapon_m249           weapon_pipewrench
    weapon_grapple  weapon_sniperrifle  weapon_displacer

Confirmed in the rebuilt hl.dll: each of the nine classnames appears twice
(registration + impulse 101 reference).

WHY 1.1.6 MISSED THREE
----------------------
I had diffed against the local reference copy
(op4/reference/dlls/player.cpp), which does contain all nine. I added only the
first six and reported it as complete. That was my error, and it is why you
saw a partial loadout. Nothing was wrong with the weapons themselves.

Also checked while I was in there, so this does not come back:

  - HUD slot/position for all nine matches the reference value-for-value
    (eagle 1/2, pipewrench 0/1, knife 0/2, grapple 0/3, m249 5/0,
    displacer 5/1, sniperrifle 5/2, sporelauncher 6/0, shockrifle 6/1).
  - iItemSlot() for all nine matches the reference bucket-for-bucket.
  - MAX_ITEM_TYPES is 6 here vs 7 upstream, but no class returns 6, so the
    6-entry m_rgpPlayerItems array is never indexed out of bounds. Bucket 6
    is a HUD-only slot.
