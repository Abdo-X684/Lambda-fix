Lambda-fix 1.1.3 - Windows package
==================================

THE ABOUT PAGE WAS LYING
------------------------
You asked for the About page number to change with every release. It was not
changing at all, and it has not since 1.0.5.

The About page prints LF_VERSION from bhl-op4/src/common/appversion.h.in
verbatim. That is a hard-coded literal - it is not derived from the package
name, the git commit or the manifest. It still said "1.0.5".

So 1.0.6, 1.0.7, 1.0.8, 1.0.9, 1.1.0, 1.1.1-diag and 1.1.2 all shipped with
the About page reporting 1.0.5. Verified in the shipped client.dll:

    before:  strings client.dll | grep '^1\.0\.5$'   -> 1.0.5
    now:     strings client.dll | grep '^1\.[0-9]'   -> 1.1.3

WHAT CHANGED
------------
1. bhl-op4/src/common/appversion.h.in  LF_VERSION "1.0.5" -> "1.1.3"
   This is what the About page shows.

2. tools/check_about_version.py - new guard.
   It reads the highest versioned directory under build-evidence/bhl-windows-mod/
   and compares it with LF_VERSION. Mismatch = non-zero exit. Run
   `python tools/check_about_version.py --fix` to sync it before packaging.

   Right now it reports a mismatch on purpose: the newest package is 1.1.3
   only after this zip is committed, which is how it is meant to work.

3. Server banner now says 1.1.3 (was 1.1.2). Text only.

FROM 1.1.2, UNCHANGED
---------------------
CPushable still has NO PushThink and NO FindTouchingEntity. Move/Use/Touch
are the working server's code. Night-vision on/off uses flashlight1 and
flashlight2.

STANDING RULE
-------------
From now on every release bumps LF_VERSION to the package version in the same
commit. If I ever hand you a zip whose About page does not match its name, that
is a defect and you should reject it.
