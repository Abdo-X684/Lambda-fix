Lambda-fix 0.1.6 - Windows package
==================================

RENUMBERED
----------
This package was published as 1.1.6. It was never a 1.x release - the
project is pre-release software and that numbering claimed a stable
interface it does not have. It is now 0.1.6 on the 0.x line, with the
beta tag starting at 0.1.8. The ZIP is byte-for-byte the same archive;
only its name changed, so its sha256 is unchanged.


impulse 101 GAVE A HALF-LIFE LOADOUT
------------------------------------
You were right. Followed the code: impulse 101 in bhl-op4/player.cpp gave 24
items and every one was a Half-Life weapon. Zero OP4 weapons.

The stock OP4 server (op4/reference/dlls/player.cpp) ends its impulse 101 list
with six more:

    weapon_eagle
    weapon_sporelauncher
    weapon_shockrifle
    weapon_knife
    weapon_m249
    weapon_pipewrench

All six are registered and compiled in our tree - they were simply never
added to the impulse 101 list. Added now, in the same order as the stock
server, and with no extra ammo calls because each weapon supplies its own
default ammo on spawn (m_iDefaultAmmo), which is how the stock server does it.

Verified in the binary - every one of the six classnames is present twice
(registration + spawn reference), same as the Half-Life weapons.

BOOST (from 1.1.5, unchanged)
-----------------------------
Hold E: you are not dragged. Release E: you are launched at the box's speed.
Implemented by recording the box's peak velocity in CPushable::Move while
+use is held, and applying it in CBasePlayer::PreThink on the release frame.
Still no PushThink, no FindTouchingEntity.

ON "IT FEELS HARDER THAN THE ORIGINAL"
--------------------------------------
I am not going to claim anything about that. You said it may be your
imagination, and I cannot run the game, so I have no measurement either way.

If it turns out to be real, the usual cause is skill settings, not physics:
our server defines 148 gSkillData fields with OP4 values in code, whereas a
stock server reads gearbox/skill.cfg. If your skill.cfg says something
different from our built-in values, damage and monster health differ - which
reads as "harder". That is testable: tell me what difficulty you play on and
I will dump our built-in values for that difficulty next to the stock cfg
ones, and we compare numbers instead of feel.
