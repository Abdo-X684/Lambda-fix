Linux client in this ZIP = OP4-based BugfixedHL client (VGUI1) with the BHLX
options menu (console: bhlx_menu). Built from tools/build_op4_bhl.py.

Install: copy the whole cl_dlls/ folder into Half-Life/bhlop4/cl_dlls/.
client.so finds vgui.so and libSDL2-2.0.so.0 in its own folder (RUNPATH=$ORIGIN),
so no LD_LIBRARY_PATH is needed.
Requirement: 32-bit libstdc++ (libstdc++.so.6 i386) must be installed, because the
OP4 vgui.so needs it. Half-Life on Linux normally already requires it.

On successful load the console prints: "[BHLX] options menu loaded".
NOT runtime-tested in this sandbox.
Windows client.dll in this ZIP is still the BugfixedHL VGUI2 build (unchanged).

SERVER (Linux): dlls/hl.so is built from the same source tree as cl_dlls/client.so.
liblist.gam points gamedll_linux to dlls/hl.so, so the stock gearbox server is no longer used.
Keep both in the same build. Not runtime-tested.

Fix: bhlx_menu no longer requires gViewPort. If the TF viewport is not created yet,
the menu attaches to the engine VGUI root. If VGUI is not ready at all, it prints:
"[BHLX] VGUI is not ready yet. Load a map, then type bhlx_menu again."

Diagnostic: with hud_speedometer 1, the first HUD frame prints one line:
"[BHL-HUD] n0=<number_0 index> h0=<number_0 sprite handle> sw/sh=<screen size> hide=<HideHUD bits> spectate=<0/1> hud_draw=<value>"
h0=0 means the number sprite file did not load (missing .spr in bhlop4 or gearbox).
A sprite index of -1 means HUD sprites did not load (sprites/hud.txt missing).
hide has bit 8 (value 8) when health is hidden by the server.

BHLX menu v2: pages General, HUD, Chat, Crosshair, Scoreboard, Models. Grey entries
("not in this build") have no feature code in this build yet and cannot change behaviour.

Crosshair (cl_cross_*) is now ported (VGUI1 FillRGBA). Default cl_cross_enable=1, as in BugfixedHL.

Kill sound (cl_killsound, cl_killsound_path) is now ported: plays on your own kills.
